Knowledge graph

When on, facts from the graph above ground story generation and validation, and each turn updates the graph automatically. The graph tools below always stay available. When off, the story ignores the graph and stops updating it; stored facts are kept. Defaults to the server's graph.enabled setting and is saved per session in the database.

Graph tools
Response generation

Streaming shows text while it is generated and requires validation to be off. Enabling either option turns the other off. Both may be off. Saved per session in the database.

Controls randomness in the story. Lower values are more deterministic, higher values are more creative. Range: 0 (exact) to 2 (maximally diverse).

0.60

Limits how many tokens one response may use. Leave the field empty to follow the server default shown as placeholder, or enter 0 for no limit. Only a limit can stop a response mid-sentence, so lower it deliberately on a smaller model. Range: 0 to 1000000. Saved per session in the database.

Context window

Turns sends the configured number of recent turns. Rolling fills the model's context window with as many recent turns as still fit: the prompts, canonical state, summaries and this turn always go out, and the older story reaches the model through its summaries. A session that chooses rolling has to name its size below. Saved per session in the database.

Rolling plans the story against this size, so a session on rolling has to name one; 32768 is a workable start for a smaller local model, and a model that reserves room for its reasoning counts that room in the size too. Turns mode ignores the size, so the field is only editable for rolling and a stored size is kept for when rolling comes back. An empty field follows the server size shown as placeholder. Range: 0 to 100000000. Saved per session in the database.
